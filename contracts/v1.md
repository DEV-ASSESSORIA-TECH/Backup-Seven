# DBBackup v1 contracts (schema 1)

## Scope and delivery

DBBackup is a Windows / PowerShell 7.2+ application. Code is shared; configuration,
credentials, locks, temporary files, pending/completed packages and logs belong
to one instance. Providers are MySQL (5.x), SQLAnywhere (17) and Directory.
No legacy configuration or artifact migration is automatic. Incremental SQL
Anywhere backups and recovery automation are outside v1's initial delivery.

Implementation branch: `release/1.0.0`. Step 7 (recovery preparation) is explicitly
excluded. Steps 8–11 integrate monitoring/limits, package/release tooling,
documentation and VERSION=1.0.0. Recovery remains external and is not a release
automation gate or a success claim made by this project.

## Public commands

`Backup.ps1 -ConfigPath <psd1> (-Job <id> | -All)` executes configured jobs.
`database` is always a full backup; directory jobs use explicit unique IDs.
`Setup.ps1 -ConfigPath <psd1>` creates an instance from the selected provider's
template, then configures credentials. `-Apply` only applies an existing file;
`-Plan` shows scheduler changes without applying them. Both require explicit
confirmation before scheduler mutations. `Diagnose.ps1 -ConfigPath <psd1>`
performs read-only checks without backup, scheduling or configuration writes.

Exit codes: 0 success; 1 operational/publication failure; 2 configuration or
dependency error; 3 instance lock busy; 4 auxiliary failure after every job
published (retention, interrupted-run cleanup, log upload or monitoring
textfile); 5 complete degraded MySQL fallback published. Precedence is
1 > 5 > 4 > 0: any failed job/retry wins over degraded, and degraded wins over
an auxiliary failure (which is still logged). Lock contention does not publish
a failed attempt.

## Configuration

SchemaVersion=1; InstanceName is a filesystem/scheduler-safe unique identifier;
Provider is MySQL or SQLAnywhere. Common sections are Tools (SevenZip, Age,
Rclone), Database, Directories, Storage (ConfigPath, RemoteRoot), Encryption
(RecipientsFile), Paths (RuntimeRoot, CompletedRoot, LogRoot), Archive
(CompressionLevel, CpuLimitPercent), Retention (CompletedDays, LogDays), Schedule.
Paths are relative to the configuration's directory unless absolute. Runtime,
Completed and Logs cannot overlap, including through filesystem links. Runtime
and Completed must use the same volume for atomic bundle transitions. Secrets
and configuration must not be inside disposable state directories. Instance
identity and roots must be unique among installed configurations. Setup never
rewrites another instance or a legacy Seven installation.

MySQL Database: Name, DefaultsExtraFile, ExtraArguments. Tools: MySql, MySqlDump.
SQLAnywhere Database: Name, ConnectionOptionsFile. Tools: DbBackup only.
Its options file contains one -c argument with UID, PWD, DBN and HOST and/or
SERVER (alias ENG; SERVER alone reaches a local server through shared memory),
optional CHARSET. DSN and startup overrides are not accepted. Connection
values containing double quotes or newlines are rejected explicitly. A private
response file passes ASTART=NO to the existing server and is deleted with its
directory when the provider ends. No dbvalid/dbeng/dbsrv is launched. V1
requires at least one nonempty .db (main database plus any dbspaces) and at
least one nonempty .log. A native failure reports the tool output with the
password removed and truncated to 2000 characters.
Directories: array of @{Id='files'; SourcePath='...'}; database is reserved.
Schedule.Tasks: array of @{Name='daily'; Job='database'; At='19:00';
Frequency='Daily'; Enabled=$true}; Weekly adds Days; Monthly adds DaysOfMonth.
Missing Schedule means unmanaged; empty Tasks means remove owned tasks only.

## Provider result

Status=SUCCESS/DEGRADED/FAILED; Packages is an array of Role, SourcePath,
ContentsOnly; Errors is a sanitized string array; Metadata contains strategy,
validation and recovery details; StartedAtUtc/FinishedAtUtc are UTC timestamps.
Providers never upload or declare remote success. Results may include useful
packages on failure. MySQL degraded requires GENERAL and GRANULAR packages;
missing either means FAILED even if the other is successfully published.
SQLAnywhere copies database and transaction log without rename/truncation;
SUCCESS means native exit code 0, expected nonempty files, archive test,
encryption and confirmed publication. It does not mean database recovery passed.

## Execution limits and monitoring

Execution.ToolTimeoutSeconds defaults to 21600 (1..86400). Every native tool
uses the same bounded process launcher; expiry kills its child process tree.
mysqldump stdout streams to disk, including detection of a failed output stream.
Execution.RunTimeoutSeconds (default 39600, 600..255600) is a deadline for the
whole run, pending retries included: each tool is shortened to the remaining
time and no job or tool starts after it, so the run still records failures,
publishes metrics and removes Work. The scheduled task ExecutionTimeLimit is
derived from it: ceil(RunTimeoutSeconds / 3600) + 1 hours (12 hours by default).
The final log upload runs after the deadline is released, limited to
min(900, ToolTimeoutSeconds) seconds.
Execution.ReserveBytes defaults to 1 GiB; EstimatedDatabaseBytes defaults to 0.
Check free local-volume space before production (estimate + reserve), compression
(staged bytes * 1.05 + 1 MiB + reserve) and encryption (archive bytes * 1.05 +
1 MiB + reserve). The database estimate is, in order: EstimatedDatabaseBytes when
positive; the last SUCCESS payload of the job (Runtime/Capacity/<job>.json)
plus 25%; a provider probe plus 25% (MySQL information_schema data+index size;
SQL Anywhere has none); otherwise 0 with a WARN in the run log. These checks do
not reserve disk against other processes and do not guarantee that a growing
source will fit.

Monitoring.Enabled defaults false. When true, Service identifies the protected
application, never the engine/software; BackupIds maps job to stable dataset ID
(default lowercase instance-job). Criticality defaults alta, optionally baixa;
ExpectedIntervalHours overrides the calendar-derived maximum gap per job.
Use the generic grafana backup contract v0.3.0 (pinned HELP fixture in tests).
Producer is dbbackup, producer_version comes from VERSION. No job/instance/host
labels are written by this producer. Alloy owns the textfile directory; DBBackup
never creates it. Errors observing or writing metrics are logged and make the run
exit 4 when no job failed and none was degraded. Observability state is checkpointed in private Runtime/Monitoring
before retention, preserving last success even if Completed or Alloy is unavailable.
Only confirmed normal FULL packages advance last_success. Retry uses the original
recovery point. Degraded publication sets last_attempt_degraded without success.
Invalid calendars warn and omit derived deadlines; failures never advance a known
deadline. Lock contention writes no metrics; failed startup with valid config does.

## Artifact and state

Names: DBBackup_<UTC>_<instance>_<job>_<run>_<role>.7z.age. Manifest schema 1
inside each package describes provider, job, run, status, roles, recovery
metadata, tool versions, relative file paths, sizes and SHA256 hashes, excluding
the manifest itself. Directory content is archived under content/, read in place
from the configured source (no staging copy in Work; 7-Zip adds the folder and
renames it to content/ inside the archive), so a file changing during the run
may differ from its manifest hash; linked files
or directories and reserved manifest names are rejected rather than followed.

Work is private and disposable. Once the .7z passes its test, the package's
plaintext payload is deleted before encryption, so payload, .7z and .age never
coexist. Each run, under the instance lock, removes
Work/<32-hex run id> and Staging/DBBackup_* directories left by interrupted runs
(plaintext dumps and transient credentials); any other item there is left
untouched and reported (exit 4). Pending is never touched by this cleanup. A tested .7z is encrypted to configured native
age public recipients (age1...). Private keys never reside in server Secrets.
Encryption writes a temporary file. An artifact bundle (payload plus state.json)
is promoted atomically from a same-volume staging directory into Pending.
state.json records schema, instance, job, run, role, local result, recovery point,
encrypted size/hash, final immutable remote destination and publication status.
Retry uses exactly these bytes and destination. Integrity mismatch fails closed.
The encrypted payload is read once to record size, SHA-256 and MD5 (state.json
Md5; computed at send time for bundles created before it existed). After copyto,
the remote object is verified from `rclone lsjson --hash` of its directory: size
must match and, when the backend reports one (S3 object metadata), MD5 must
match; otherwise the upload is logged as size-only. The local file is not read
again and the remote object is not downloaded/decrypted. A pending bundle is
re-hashed (SHA-256) before every retry; one created in the same run is not.
After copyto and remote verification, bundle moves to Completed; a crash between
upload and move is safely retried. State is metadata, never credentials.
Completed means transport confirmed, not successful database recovery. Only
Completed participates in age retention; Pending is never age-deleted.
Retention checks state, ownership, payload presence and size, not the SHA-256
of every retained payload. A bundle or log that retention cannot read is
reported and skipped; the remaining items
are still processed and the run exits 4. Retention.KeepLocalPayload (default
$true) keeps the encrypted payload in Completed; $false deletes it right after
confirmed upload and marks state.json LocalPayload=REMOVED (size/hash kept).
Remote retention belongs to the bucket (e.g. S3 lifecycle rules). Each run logs
how many bundles and bytes are still waiting in Pending per job.
Storage.Destination (default s3) is only the destination label for metrics.

## Secrets and scheduler

Each instance owns Secrets, including mysql.cnf / sqlanywhere.options,
rclone.conf and recipients.txt. Native option files may contain plaintext
passwords and require NTFS ACLs allowing only SYSTEM and Administrators.
State directories (Runtime, Completed, Logs) are made private only when DBBackup
creates them. A backup run never rewrites permissions of an existing directory;
Setup -Apply protects an existing one only when it is empty, refuses a populated
directory with foreign permissions, and Diagnose fails on a non-private one. No
password enters a process command line, task action, log or manifest. SQL
Anywhere gets its connection through @options-file. Only vetted -c connection
options are accepted; backup control flags cannot come from the secret file.

Tasks live in \\DBBackup\\<InstanceName>\\, run as SYSTEM with a fixed absolute
configuration path and explicit job, and have a config-path ownership marker.
Setup never enumerates legacy tasks for deletion. Foreign tasks in the same
folder cause a conflict, not adoption or deletion. Applying setup to two
instances cannot affect the other's tasks, secrets or state.

## Recovery and qualification boundary

Transport checks and archive tests do not prove restorability. Actual decrypt,
restore and database validation are external responsibilities, not claimed by
unit tests and not performed by package/release workflows.
No production connection, user provisioning, old-task disablement, release or tag
is performed by development checks. 7z/age/rclone/SAP/MySQL binaries are external.
